# H5 演示质量门禁（V2.1）

## 预检：先验内容，再排版
先检查源稿逐页质量记录（content_quality）、听众任务、事实/假设、证据、边界。问：删掉本页会损失什么？如果只有口号、空泛背景、标题复读、泛用三点且无具体支撑，不能靠美化交差。联用回传 slide_id/缺口/建议补证或合并；独立使用在本 Skill 内澄清、精炼并经授权更新源、revision/hash/逐页评审。不能凭空补案例、数字、阈值。已有稿可原样预览，明确不足和未评审状态。旧契约解析兼容，不自动晋级。

## 视觉设计
- 先选信息关系，再选组件。真实可比数量/趋势→图表；机制/流程/架构→结构图；选择/验证→对照矩阵或判定路径。无数量不伪造图表；表格适合精确逐项比较；箭头必须表示真实顺序或关系。图示标签优先，短文本适用于单一判断。不要为达图表比例而强行作图。
- 一页一个主要判断；标题给结论，Takeaway 给意义/限制，正文给证据。画面不出现长篇口述段落，文字提炼为可投屏的短语、数据、标签；解释、例子、机制展开和追问放 Talk/Delivery/Fallback。迁移细节须在内容源修改并保留可追溯性，关键限制、证据、口径仍在画面，不能藏在备注中。
- 首屏视线自然从标题到核心视觉；避免短表格在大画面中央漂浮、首尾断裂或无意义填满。稀疏普通页先判断信息是否不足、是否可合并；内容充分则增大核心视觉的阅读尺度，采用合理列宽、分组、行距与相邻布局；不增加装饰、空卡、假数据或超大字号凑面积。封面、章节过渡、单一行动页可有意留白，说明理由。留白服务信息层级，不设面积硬 KPI。
- 1366×768 和 1920×1080 实际检查标题→结论→证据的间距、阅读尺度、行列对齐、关键标签、对比度、内容不溢出；不因只过结构/保真就通过。
- 导航是工具而非内容。观众普通视图：右下透明平面，页码小字、常态弱化，按钮透明，悬停/键盘聚焦恢复可读性、焦点可见；不使用胶囊底、常态阴影、鲜艳高亮、强动效。控件保留操作区域和 aria-label，触屏提高可见性；观众双屏、打印、预览隐藏（原引擎逻辑）。不遮挡任何正文；演讲者页码保持原有可读性。禁止在单页覆盖共享导航样式。

## 验收与回传
render-review.json 的 `content_quality` 记录上游/独立评审状态；`page_reviews` 以 slide_id 为键，逐页记录：
`substance`、`visual_fit`、`concise_visible`、`notes_detail`、`hierarchy_spacing`、`navigation` 各为 pass / revise / not_tested，附 `basis`（具体观察及有意留白理由）。全量通过才可正式验收；未实测画面不得填 pass。若有稀疏/拥挤/错误图示/复述，标 revise 并记录页号、具体问题、拟修订；结构脚本不是主观设计或说服力证明。复杂图表人工核对真实数据映射与限定，静态保真不足以证明视觉正确。真实听众评价另行验证。
