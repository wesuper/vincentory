# 沟通价值闭环（内容侧）

## 先决定值得解决的问题
用一张内部诊断卡：听众任务、当前可证认知、最关键障碍、候选洞察、证据、反例、会议可达结果。优先解决改变结论的问题，不追求填满字段。
洞察不是新术语：它应改变一个判断、解释一个反常现象、揭示约束或提供可迁移方法。若材料仅支持常识，坦率交付清晰常识，不强造惊喜。
候选洞察依次检查：与听众相关？比现有理解增加什么？有什么证据？竞争解释是什么？什么条件会推翻它？会改变什么选择？无证据的洞察标为待验证假设。

## 主动听下去的理由
逐段检查「为什么与我有关 → 我现在知道什么 → 下一步有什么真实问题值得解决」。开头给价值承诺，关键问题在后文兑现。领导会议先结论和选择；技术分享可先预测反常例；风险会议不得延迟披露。删除无信息增量的段落。不要强行故事化、制造焦虑、使用假悬念或以情绪替代证据。
讲者与听众同频：在真正有误解风险的节点安排复述、预测、选择或情境练习；自然停顿；若发现误解，回到最小例子/关键证据，再检查一次。未观察到反馈就是未知。

## 三轮独立视角审查
第一轮仅看可见核心页，复述结论、限定和行动；第二轮再看证据台账，提出足以推翻主张的反例及替代解释；第三轮以执行者/同行/评委视角尝试执行、迁移或映射真实标准。分别记录输入范围、发现、严重度、证据页、修订及复查结果。单个 Agent 的角色模拟不是独立真人审查；有实际第二审查者才标外部审查。严重缺陷回 REVIEW，不靠平均分抵消。没有材料支持时缩小目标。
对晋升答辩特别追问：关键个人判断与团队贡献的区别、困难程度、可归因影响、复用杠杆；对方案特别追问不做和替代方案；对深度分享特别追问反例、复现与迁移。

## 五维效果计划
需要正式效果评估或会后复盘时，在会前建立 effectiveness-plan.json（协议见 effectiveness-contract.md）。只选择与场景相关的维度，其他写不适用理由。每项给基线（未知可明示）、成功标准、实际采集方式、时间窗口、负责角色和真实页 ID。至少一个适用维度。标准在观察前固定；变更须新计划，不回填旧观察。
- insight：听众指出一个新的、准确且有价值的判断；自报新颖性不是事实正确性的证明。
- understanding：不看材料复述结论和关键限定；可用情境题检验。
- credibility：最强异议能否依据可追溯证据得到回答；允许有依据地不接受主张。
- transfer：在新情境预测、复现或应用；区分即时练习与后续真实应用。
- action：实际权限内作出决定或执行下一步；区分意向、决定、执行、业务成效。
不强制收集满意度，不强制每页提问，不收集不必要的个人信息。

## 会后复盘
仅在用户提供真实记录后建立 effectiveness-observations.json。逐项保留来源、时间、观察事实、与标准比较的结果、局限；沉默、掌声、未回消息不能推断理解或同意。合成/排练数据独立标记，不能混入真实记录。无观察则 unknown；未达成不等于内容失败，可能是权限、资源、外部条件、证据或表达问题。
生成效果报告后，定位差距：目标错误 / 洞察不足 / 证据不足 / 表达与节奏 / 执行约束 / 未知。提出最小修订、责任角色、下一次检验；区分观察与原因假设。不要自动把个人评价、会议记录或内部反馈写入 H5。修订源稿须走内容 revision/封存流程；效果记录绑定对应稿件和计划，修订后不能沿用为新稿的成绩。
