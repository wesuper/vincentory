# 视觉路由：先明确页面任务

目标不是每页不同花样，而是让主要信息在第一眼可定位，第二眼能读懂证据，追问时能核查。主题仅是皮肤；默认 light-gradient，本轮明确指定优先。组件细节见主 Skill 直接链接的 page-templates。

| 任务 / 信息关系 | 优先组件 | 注意 |
|---|---|---|
| 单一结论 + 定量证据 | stats-row / stat-card + footnote | 基线、单位、日期、分母和范围；无数据不用伪数字 |
| 同口径方案比较 | mini-table 或 exp-grid | 同维度、同基线，说明差异及代价；不默认给排名 |
| 因果与机制 | chain-grid / Mermaid / 本地 SVG | 箭头代表真实关系；相关性不得画为因果，假设用可见标签 |
| 技术架构/集成 | 分层 SVG 或 Mermaid + 文字说明 | 标注数据流、权限/边界、失败路径；核心图离线有兜底 |
| 进度与路线 | timeline / week-panel | 已完成、计划、依赖/不确定清楚区分；未知日期不造 |
| 风险/异议 | risk-cards / 方案比较 | 风险、条件、应对、owner（未确认就标拟定） |
| 市场机会或趋势 | ECharts / 表格 | 来源、样本、量纲；不把不可比口径画成趋势；网络失败可读 |
| 并列定性证据 | card-grid / list | 按关系分组，避免把所有页面都做三卡片 |
| 行动/决策 | qa-page / ask-card 或内容页 | 请求、负责人、时间、验收；分享场景改为应用方法，不强行审批 |
| 追问证据 | fold-section 或已有附录 | 观众先看核心证据；关键限制不能折叠隐藏；附录 ID 保持不变 |

## 受众适配
领导：突出结论、选项、风险与决策点；客户：场景、价值、边界、验证与下一步；同行：机制、实验、数据和复现；晋升评委：职级标准与可归因证据、复杂性、影响、成长。听众混合时主线优先主要听众，技术明细由授权附录支撑。布局不修改论证。

## 模板约束
传统正式 deck 使用原有封面胶囊、目录逐章结论、内容三段式和收尾；若源没有目录、只有一两页、没有封面/收尾，使用 adaptive，不造页。封面/目录/收尾内容太复杂或超出模板时可改三段式，保留原语义角色与 ID。标题、Takeaway 和展开证据互补，不复述三遍。复杂图表/架构由 Agent 根据实际内容人工生成，基础脚本只支持安全的简单 Markdown 到模板映射。

## 视觉优先与投屏密度
优先能真实编码关系的图表、流程、架构、矩阵；卡片不等于图示，纯文字仅在更直接时使用。准确数据、标签及关键限制保留在画面，口述细节由 Delivery/Fallback 补足。短表紧随判断，用大而清楚的行间距及列宽而不是在剩余空间垂直居中；只在内容确实充分时放大图示。基础渲染器的显式 `flow:` 可将 2–4 个 `###` 分组渲染为带方向的步骤链；只有源已表达顺序才使用，任意并列分组使用普通网格。更复杂的条件分支/真实数据图需要 Agent 按实际内容完成。见 [presentation-quality](presentation-quality.md)。


## 显式关系与听众任务
先识别 Visual Intent 的 `prefix:`（旧自由文本保持兼容）；例如 `risk: 风险表；包含 comparison` 应选择 risk，不能被描述中的 comparison 抢路由。`decision`、`change` → comparison，`expectation` → timeline，`attribution` → table，`mechanism` → architecture，`learning`/`action` → content；建议布局不等于已生成复杂图。依据 [同频展示手册](audience-synchrony.md) 控制跨页编码、讲述注意点、真实边界和核心路线。
