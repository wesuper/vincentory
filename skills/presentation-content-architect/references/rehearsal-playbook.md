# 现场沟通设计与反方预演

## 一页不是一段文案，而是一次认知交接
逐页写 journey：beat（orient/tension/explain/prove/decide/practice/close/appendix/transition）、audience_shift、question、listen_cue、check、recovery、priority（core/deepening）和 basis。把理解路径和原有信息增量相互核对。例：机制图 → 讲者先说明图例 → 指向入口节点 → 问/观察听众能否预测下一状态 → 若不能，改用最小输入输出例子 → 回到原机制 → 转场。无需每页强制提问；只在认知风险或决策节点采用自然检查。不得暗示可自动读取听众心理。
- 开场：一句实际关联、一个真实问题/结论、听众收获。紧急风险先直接报状态和请求。
- 口述：短句、自然语言、信号词，按「看哪里→为什么→意味着什么」引导；不读表格全文。不同时给复杂视觉和无关口述。
- 认知负载：先给必要术语/图例，复杂机制分段解释；对照、例子与必要标签相邻；删除与任务无关的装饰。
- 停顿：在关键取舍、反常结果、需要辨识图形或做决定处留时间；单页时间含停顿。讲者不依赖自动计时翻页。
- 收尾：准确重复核心判断与条件，检查复述/选择/练习；行动型明确请求、拟责任与时间/检查点，知识型给迁移任务或实践入口。

## 三视角压力测试（记录实际推演，不声称真人反馈）
1. 主受众：只看标题串+核心证据，能否复述最重要结论及限制？在何处失去线索？
2. 怀疑者：找会推翻结论的一条反例、未验证前提或替代；列问题、证据所在页、回答、不能回答的边界和后续核查。
3. 执行者/技术同行/评委（按场景）：能否落地、复现、按真实标准评价？责任、权限、异常、停止和验证是否明确？
若反方正确，修订主张而非润色回答。qa 放内部工作态；只有允许随文件流转的回答可写 Fallback 和 Speaker Notes。Q&A 证据跳转以 slide_id 和实际页序定位，不编造附录。

## 时间被砍或被打断
- core 是在最短可用路线中必要的判断、证据、风险、限定和行动；deepening 是可独立跳过的进一步展开。不能为短路线删掉限制、破坏因果或跳过必要前提。没有安全可跳的页，用 same。
- short_route.slide_ids 必须按原页序等于全部 core，minutes 为保留页 Notes.Minutes 合计。它是**这些页面的备注预算**，不是现场计时保证。讲者还须预演跳过页后的转场；不能把空余时间当承诺。
- 被打断：确认问题→简答结论和边界→必要时跳证据页→回到主线问题；若对方要求改目标，记录变更，别现场许诺未授权行动。
- 演示/网络失败：关键证据有可读静态备份，未验证 demo 不称已经成功。
- 讲稿要有合适的短句及现场恢复；核心路线可以跳过深挖，观众仍有完整可独立理解的逻辑。

## 预演五项记录（working-state.experience.rehearsal）
recall：不看备注准确复述核心判断与限制；objection：最强异议答到证据/边界；compression：核心路线不漏决定性信息、跨页可恢复；synchrony：口播指向可见证据、转场/术语/互动时机；action：结尾与权限、下一步/知识应用及信号一致。每项写 result + 具体 basis；revise 回退，not_applicable 说明理由，不得用总分覆盖致命缺陷。机器只检查记录完整性，实际演讲/测试需真人。

## 会后真实闭环（独立复盘文件）
记录实际听众的问题、误解、决策/未决、行动人/日期（已确认才记录）、实际采用或学习验证，区分观察、推断、后续计划。会前不填写假听众评价。内容/意图/预演发生变化时提高 revision 并重封，实际会后观察独立于已封存源稿、工作态和效果计划，不修改历史记录；需修订时创建新 revision 和新计划。
