# 逐页内容质量门禁

## 在主线设计时反推
先问：听众看完这页能获得什么此前不知道的、能解释/判断/执行的东西？它回答哪个具体问题？删除这页后会失去哪条判断依据？如果只损失口号、重复标题或过渡句，合并或删除。封面、目录、章节过渡、单一决策/金句页可以有意简洁，但须有场景理由，不强制凑字数。禁止把主线每页写成「背景—意义—措施」的空泛套话。

每页至少存在一种与任务相关的具体支撑：事实与来源、真实数据/对照、可核查机制、带边界的案例、明确差异与取舍、具体步骤与验收逻辑。以上不是固定数量指标；证据缺失不能靠多写三条观点补足。先问用户最影响结论的缺口；如果暂缺事实，可以将页改为明确标记的假设、拟议方案或验证设计（明确对象、测量、判定及失败处理），仍缺支撑则保持 REVIEW 或合并。不要编造客户、收益、阈值、执行承诺。

## 图表优先，文字提炼，口述展开
1. 先确定信息关系：数量/趋势/构成→真实数据图；对比/精确口径→矩阵或表；过程/机制/架构→关系图、流程图或分层图；决策→条件分支/风险矩阵。无数据时不画虚假定量图；无顺序时不加箭头。单句判断或叙事无法图示时保留简短文字。图表优先是适用性判断，不是图表比例 KPI。
2. Visible 只保留读者需要现场看到的具体事实、关键数字、短标签、比较维度、核心依据和必要边界。标题给判断，Takeaway 给意义/限制，证据区让判断有抓手；三者不能重复。使用 Markdown 分组、短标签、表格或结构化数据表达关系；Visual Intent 说明关系及首选表达，而非 CSS 类名。真实图表所需数据、单位、时间、口径、允许公开的来源必须可获得。
3. Talk 是现场提示（2–4 条、每条≤40 字）；Delivery 写单行详细口述（为什么、如何、举例、取舍），Fallback 写追问/不确定性；Transition 衔接。备注不能复读 Visible。关键限定、比较口径和决策条件不得只在备注，备注也不得泄露未获许可的信息。时间预算决定口述展开程度。

## 逐页评审并落盘
working-state.json 记录 `quality_profile: "slide-review"`，`slide_quality` 以全部 slide_id 为键，每项：

```json
{
  "result":"pass",
  "audience_question":"听众要用什么依据判断是否继续？",
  "information_gain":"效率、质量和权限各有不同验证对象及失败处理",
  "support":"拟议评估矩阵；尚无真实试点数据，不承诺收益",
  "visual_reason":"同口径逐项比较需要精确标签，矩阵优于长段落",
  "notes_gain":"口述解释配对任务、复核争议、权限失败即停",
  "basis":"检查过正文、证据和口播；关键边界可见"
}
```

对有意留白的页在 basis 解释其必要性。未通过用 result=revise；先修订内容源再复核。代码只能检查记录、字段、明显占位及精确复述，不能判断证据真实性或说服力。未完成本轮评审的稿不能宣称通过内容门禁；H5 可提供安全预览，不得正式验收。发布前仍需人工确认。


## 同频检查（按需深化）
原 slide_quality 不变；启用听众旅程扩展时 journey 补充每页的听众起点、希望改变的判断、视线/讲述提示、理解检查或观察方式、困难时的恢复及优先级。只有在上游已确认的关系与内容支持时，才将需要展示的提示写入 Notes.Cue/Advance/Interaction；不要求观众每页互动，也不把内部听众画像投屏。听众从哪里来、看到什么、为何接着听下一页，应能从标题串、备注和可见证据一致推导。短路线遗漏任何关键结论、条件或必要证据，必须重新划分 core/deepening。
